# 행사 관리하기

여러 팀에 걸친 행사를 한 화면에서 관리하는 기능. `explore.pen` 참고.

## 문제

지금은 행사를 수정하려면 **참여 팀 → 팀 상세 → 해당 행사 → 수정** 으로 들어가야 한다.
팀이 여러 개면 어느 팀에 있던 행사인지 기억해서 팀부터 골라야 하고, 팀을 오갈 방법이 없다.

예: GDG 팀과 쿨냥이 팀에 속해 있고 각각 행사가 2개, 3개 있을 때 → 5개를 한 화면에서 보고 싶다.

## 결정

| 항목      | 결정                                    | 근거                                                                     |
| --------- | --------------------------------------- | ------------------------------------------------------------------------ |
| 목록 범위 | 어드민으로 속한 팀들의 모든 행사        | 어드민이 아닌 팀 행사를 보려면 팀 상세로 가면 된다                       |
| 팀 구분   | 팀별 섹션으로 나누지 않고 한 목록       | 팀 수가 늘어도 스크롤이 길어지지 않음                                    |
| 팀 필터   | 가로 스크롤 칩 (전체 / GDG / 쿨냥이)    | 값이 사용자마다 늘어나는 축                                              |
| 상태 필터 | 밑줄 탭                                 | 값이 고정된 축. `ParticipatedEvents`가 이미 쓰는 패턴이라 학습 비용 없음 |
| 진입점    | 마이페이지 > 이벤트 카드에 세 번째 항목 | 어드민인 팀이 없으면 항목을 숨긴다                                       |

## C와 D는 경쟁 관계가 아니다

- **D** = 진입 구조. `참여 행사`와 `관리 행사`를 별도 메뉴로 둘지, 한 화면 세그먼트로 합칠지
- **C** = 목록 안쪽. 상태를 필터 탭으로 거를지, 섹션으로 나눌지

축이 달라서 D+C 조합이 가능하다. 실제로 정할 건 두 가지다.

## 행사 생성

행사는 반드시 팀에 속하므로, **어디서 만드느냐가 곧 팀을 언제 고르느냐**를 결정한다.

진입 = **B안**(마이페이지 `내 행사` 단일 메뉴 + 세그먼트), 목록 = **D안**(참여/관리 세그먼트 + 팀 칩)로 확정. 관리 화면은 마이페이지 > 내 행사 > `관리 행사` 탭이다.

| 진입점                    | 판정     | 팀 선택    | 이유                                                                         |
| ------------------------- | -------- | ---------- | ---------------------------------------------------------------------------- |
| 헤더 `+` → 팀 선택 시트   | **추천** | 시트에서   | 세그먼트를 오가도 늘 같은 자리 → D안과 충돌 없음. 팀 하나면 시트 생략        |
| 이벤트 목록(홈) 헤더 버튼 | 대안     | 폼에서     | 발견성 최고. 단 어드민 아닌 사용자에겐 숨겨야 하고, B안과는 별개 진입점이 됨 |
| 팀 상세의 `+ 행사 만들기` | 보조     | 불필요     | 팀 맥락에서의 보조 경로로 유지. 관리 화면의 대체는 아님                      |
| 목록 위 FAB               | 제외     | 필요       | **D안과 충돌** — 참여 탭에도 뜨거나 탭 전환마다 깜빡임                       |
| 목록 끝 점선 카드         | 제외     | 불필요(칩) | 발견성 최저                                                                  |

폼은 `EventEdit`의 4단계 구조를 그대로 쓰고 맨 위 `팀`만 달라진다 — 정해진 채로 왔으면 자물쇠 아이콘의 읽기 전용, 목록에서 왔으면 필수 선택 필드.

## 백엔드

`SharEv-Backend/docs/event-admin-backend.md` 에 정리. 요약:

- 생성/수정/삭제 API와 어드민 검증은 **이미 있다**. 프론트 화면만 없음
- 신규 필요: `GET /gatherings/managed`(어드민 팀들의 행사 통합) + 응답에 `teamId`/`teamName` 추가
- 결정 필요: 종료 행사 수정을 서버가 막을지(프론트 표시만 vs `update` 검증 추가)

## 열린 질문

**`참여 행사`와 역할이 헷갈릴 수 있다.** 마이페이지 같은 카드 안에 나란히 놓이는데 기준이 다르다.

- `참여 행사` — 내가 **카드를 만든** 행사. 팀 개념 없음
- `행사 관리하기` — 내가 **어드민인 팀**의 행사

내가 만든 GDG 행사에 내 카드도 만들었다면 두 목록에 같은 행사가 동시에 뜬다. 메뉴 라벨이나 설명으로 구분이 되는지 시안에서 확인 필요.

**상태 필터 라벨을 무엇으로 할지.** "수정 가능/불가"는 결과를 말하고, "진행 중/종료"는 원인을 말한다.
후자가 기존 화면과 일관되지만, 이 화면의 목적(수정)에는 전자가 직관적일 수 있다. 시안에서 두 안을 비교한다.
